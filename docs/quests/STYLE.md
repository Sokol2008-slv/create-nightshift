# Квест-бук «Ночной смены» — как писать (ночь 30.09.2026)

Задача от Георгия, дословно по сути:
- «сделать квест-бук таким, чтобы прям хотелось читать» — польза + юмор;
- «прикольные описания, шутки связанные с компанией… и не только про Axiomativ, разные прикольные, можно чернуху»;
- «не плодить лишние ветки/страницы: есть страница „Еда“ — и там всё, что надо, даже если длинная»;
- «энергия — это сначала колёса, потом пар, потом электро, потом ядерная» — одной веткой по порядку;
- «инфу про провода: какой сколько проводит», «про магниты — кто и сколько вырабатывает»;
- «в ракетостроении я вообще не понимаю, что делать и как подготовиться к вылету — пояснять чётко, что и как,
  может ссылки на инфу давать»;
- «проверь пару раз, чтобы там не было месива» (линии, налезающие карточки).

## 1. Польза — главное
- Первая строка описания — ЗАЧЕМ это игроку (одна фраза). Дальше — КАК: какая машина, из чего, где взять,
  что подключить, в каком порядке. Конкретно, пошагово, без «изучи сам».
- Числа (FE/т, SU, об/мин, урон, прочность, дальность, мБ) — только проверенные: из кода/конфигов мода, из
  `docs/VAHTA-GOTCHAS.md` (раздел «Энергия» — там всё посчитано), из `kubejs/` пака. Не уверен — не пиши число.
- Пак НЕ ванильный: руками крафтят мало («Вахта» — руками только собирать, остальное — машины Create),
  рецепты переделаны KubeJS. Перед тем как писать «скрафти X», проверь рецепт: `grep -rn "<id>" kubejs/`,
  дамп рецептов `tools/data/recipes-dump.json.gz` (gzip JSON). Не уверен в рецепте — пиши «рецепт — в JEI (R)».
- Длинное — на страницы: отдельная строка `{@pagebreak}` внутри `desc`.
- Ссылка на внешнюю инфу — отдельной строкой описания в формате JSON-компонента (FTB разбирает строку,
  которая начинается с `{` и кончается `}`):
  `{"text":"▶ Вики: ракеты Northstar (открыть)","color":"aqua","underlined":true,"clickEvent":{"action":"open_url","value":"https://…"}}`
  Только реальные адреса (проверь WebFetch, что страница открывается и про то). 0–2 ссылки на квест, не больше.

## 2. Юмор
- Мир: игроки — вахтовики компании **Axiomativ**, смену перебросили на «Вахту»; штаб компании — планета
  Аксиоматив. Девизы компании: «Свобода от рутины», «Всегда есть решение», «руками только собирать».
- Формат: последняя строка описания, серым курсивом: `&7&o…&r`. Одна-две фразы. Не в каждом квесте —
  примерно в каждом втором-третьем, зато смешно. Польза ВСЕГДА выше шутки.
- Жанры (смешивать): служебные записки отделов Axiomativ (ОТК, бухгалтерия EMC, отдел кадров, техника
  безопасности, столовая, юротдел, отдел по работе с ордой, пресс-служба, служба доставки), бытовые наблюдения
  игрока в Minecraft, чёрный юмор про смерть/орду/взрывы/радиацию (можно), абсурд, отсылки к играм и мемам.
- Примеры тона:
  - `&7&o— Служебная записка ОТК: «Паровой котёл без воды — это не котёл, а очень дорогая печка».&r`
  - `&7&o— Техника безопасности: реактор взрывается один раз. Потом техника безопасности уже не нужна.&r`
  - `&7&oЗомби не умеют открывать двери. Но они умеют ждать. И грызть. В основном грызть.&r`
  - `&7&o— Отдел кадров напоминает: скафандр — не дресс-код, а условие выживания. Хотя и дресс-код тоже.&r`
  - `&7&oБухгалтерия: «Трансмутация — это не воровство, это оптимизация налогообложения».&r`
  - `&7&oЕсли ракета не взлетела — это не провал, это очень короткий полёт.&r`
- Нельзя: реальных людей по имени (ни Георгия, ни Эльхана, ни кого-то ещё), политику, национальности, религию,
  мат, 18+, валюты ₽/₴/€ (деньги — EMC или «$»), упоминание n8n. Не унижать игрока. Чернуха — про игровые
  смерти, орду, взрывы, монстров, а не про реальные трагедии.

## 3. Структура: меньше страниц, плотнее
- Одна тема — одна глава, даже если длинная. Не создавай новые главы без крайней нужды (сливай в существующие).
- Похожее сливай: вместо пяти квестов «сделай каждый вариант» — один квест на главный предмет + перечень
  вариантов в описании. Удалять дубли можно (прогресс по ним пропадёт — не страшно).
- Справка (цифры, таблицы, «сколько что даёт») — квест `"type": "checkmark"`, `"optional": true`,
  `"shape": "circle"`, иконка — сам предмет. В описании — таблица строками:
  `&eМедный провод&r — 1 000 FE/т, пролёт 16 бл.`
- Заголовок раздела внутри главы — можно `checkmark` с `"shape": "diamond"` и описанием «что будет дальше».

## 4. Раскладка без месива
- Ручная: у КАЖДОГО квеста главы `"pos": [x, y]`. Главный путь — слева направо по y≈0, шаг x 2.0–2.5;
  ответвления — рядами выше/ниже (шаг y 1.5–2), стадии — колонками. Цели (`"goal": true`) крупнее — оставь им
  место (размер 1.6).
- Зависимости — только настоящие («без этого не сделать»). Меньше перекрёстных линий: если квест нужен многим,
  подумай, не лучше ли одна связь от «узла стадии». Справкам — без зависимостей или `"hide_lines": true`.
- Проверка ОБЯЗАТЕЛЬНА: `python3 tools/quest_preview.py <папка> <ключ_главы>` → открой PNG (Read) и посмотри:
  линии не пересекаются и не идут сквозь карточки, подписи не налезают, путь читается слева направо.
  Проверь минимум два раза (после раскладки и после финальных правок).

## 5. Техника
- Формат спецификаций — шапка `tools/gen_quests.py`. Свои файлы: `tools/quests/<твои>.json`.
- После правок: `python3 tools/gen_quests.py` — должно быть без «ОШИБКИ». Он сверяет id предметов по jar-файлам
  модов клиента (`~/.var/app/org.prismlauncher.PrismLauncher/data/PrismLauncher/instances/NightshiftDev/.minecraft/mods`)
  и `kubejs/startup_scripts`. Не найден — ищи верный id в `assets/<ns>/models/item/` jar'ов.
- Сгенерированное (`config/ftbquests/`) НЕ коммитить: после проверки `git checkout -- config/ftbquests`.
  Коммитить только свои `tools/quests/*.json` (и свои docs). Префикс `[claude] quests: …`, трейлеры:
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>` и
  `Claude-Session: https://claude.ai/code/session_01FwaEjbYjaWxo24bM3r4pbh`. Без push — сольёт главный.
- Ключи, на которые ссылаются ДРУГИЕ главы, не менять и не удалять: `altar:wave_15`, `altar:wave_50`,
  `altar:wave_70`, `ore_processing:brass_ingot`, `ore_processing:crushed_ore`, `space:interplanetary_alloy`,
  `create_basics:shaft`, `create_basics:large_cogwheel`, `brass_logistics_trains:brass_casing`.
  Если сливаешь главу или переносишь квест — ставь перенесённому `"id_as": "старая_глава:старый_ключ"`
  (прогресс игроков сохранится). Если на него ссылались снаружи — в отчёте перечисли «старый адрес → новый»,
  ссылки в чужих файлах поправит главный (генератор при сборке покажет их как ошибки — это ожидаемо).
- Порядок глав (`ORDER` в gen_quests.py) не трогать — новые/слитые ключи перечисли в отчёте.
- Не трогать: `tools/gen_quests.py`, `kubejs/`, моды, серверы. Не запускать Minecraft/серверы, не убивать java
  (на машине открыт игровой клиент).
