# Create: Ночная смена — арсенал, бестиарий и баланс набегов

Источники: рецепты и lang-файлы из jar-ов мода (data/*/recipe, munition_properties, assets/*/lang), плюс `create-guardian-beam-defense-1.3.3b-1.21.1` (скачан отдельно с Modrinth только для чтения, в паке НЕ установлен) и веб-поиск по кандидатам-мобам. Числовой урон/скорость там, где мод хранит их в JSON (`munition_properties`, `weapons/*.json` у Gunsmithing) — **точные значения из данных**. Там, где атрибуты моба/оружия зашиты в Java-байткоде (почти все хоррор-мобы, ваниль), числа — **экспертная оценка** с пометкой; проверяйте живьём через **Jade** (уже стоит в паке — наведение показывает HP).

Условные обозначения фаз: P0 Выживший · P1 Разнорабочий · P2 Латунь · P3 Пар и глубина · P4 Сталь и нефть · P5 Энергия · P6 Космос.

## 0. Материальный гейт — что на самом деле открывает каждая фаза

Прежде чем расписывать арсенал, важное открытие: **гейты по факту завязаны не на "фазу" как понятие, а на конкретный промежуточный предмет Create/аддонов**. Вот жёсткие зависимости, которые нашлись в рецептах:

| Предмет-гейт | Рецепт | Реальная фаза |
|---|---|---|
| `create:andesite_alloy` | андезит + самородок железа | **P1** (нужно только железо, но это база Create с первого дня) |
| `create:precision_mechanism` | 5-шаговая последовательная сборка из **золотых пластин** | **P2** (Латунь — "цинк, золото → механизм точности", ровно как в задумке) |
| `create:brass_casing` / `c:plates/brass` | цинк + медь → латунь | **P2** |
| `createbigcannons:guncotton` | база-порох + **редстоун** (нитро-окислитель) + вода, нагрев | **P3** (редстоун открывается в P3) |
| `createbigcannons:nethersteel_ingot` | 4×сталь/8×чугун + **осколок незерита**, супернагрев | **P3** (Нижний мир) |
| `tfmg:steel_mechanism` | никель-лист + свинец-лист + сталь-шестерня | **P4** (ровно "свинец/никель/литий") |
| `tfmg:thermite_grenade` | **алюминий** (TFMG) + термитный порошок | **P4** |
| убийство Guardian / Elder Guardian | дроп для Guardian Beam Defense | практически P3 (нужна приличная броня против стражей) |

Отдельная находка, важная для задачи 3: **большая пушка (не автопушка) физически собирается уже в P1** (лафет/лоток/ствол — андезит+чугун+порох), но **стрелять из неё нечем до P3**, потому что пороховой заряд (`powder_charge`) делается из `packed_gunpowder` = **гуcкотон** = редстоун. То есть у команды в P1–P2 может простаивать полностью построенная, но немая пушка — это стоит либо явно объяснить игрокам, либо считать "долгостроем впрок".

### 1.2 Create-ловушки (базовый мод Create)

|---|---|---|---|

**Металл стволов автопушки** (только 3 тира, нашёл в block_recipes): **чугун → бронза → сталь** (нет нижнестального тира для автопушки).

|---|---|---|

| Бронза | медь+олово ИЛИ медь+цинк+пепел-Create ИЛИ 2×латунь+пепел | **P2** (обычно через цинк/латунь) |
| Сталь (**своя, не TFMG!**) | 2×железо + уголь, нагрев в миксере | **P1/P2** технически (не нужен ни редстоун, ни незерит) |
| Нетерсталь (только для больших пушек, не автопушки) | 4×сталь ИЛИ 8×чугун + **осколок незерита**, супернагрев | **P3** |

**Боеприпасы автопушки — точные данные (`munition_properties/projectiles`):**

| Патрон | Урон | Пробитие | Особое | Мин. фаза (материал патрона) |
|---|---|---|---|---|
| AP-патрон (Armor Piercing) | **14.0** | 2 | игнорирует неуязвимость (не броню), лучший против "мягких" целей | **P2** (гильза из латуни) |
| Flak-патрон | **10.0** прямое + разлёт **15 осколков**, взрыв.сила 2.5 | 1 | против воздуха/толпы, шрапнель на площади | **P2** |
| Пулемётный патрон (свой, отдельный от Gunsmithing) | **8.0** | 1 | низкая отдача, самый дешёвый (медный самородок+порох) | **P2** |

Патроны собираются через `sequenced_assembly` (прессовка листа → гильза → набивка порохом — **обычным ванильным порохом**, не гуcкотоном!). Контейнер боеприпасов (`autocannon_ammo_container`, латунь+железо) заполняется **деплойером** (спец. рецепт `filling_deployer`) — обычная воронка Create прекрасно кормит деплойер заготовками и забирает готовые патроны из контейнера, т.е. линию легко зациклить конвейером.

**Большая пушка (артиллерия, ручное заряжание через cannon_loader):**

| Снаряд | Урон | Особое | Материал | Фаза (реальная — с учётом пороха!) |
|---|---|---|---|---|
| Ядро/Shot (простое) | **30.0** | пробитие 1.1 | камень+доска (**бесплатно!**) | **P0/P1** по материалу, но нечем стрелять |
| Мортирный камень (drop mortar) | **~30** (то же munition, падает по параболе) | навесной огонь через стены | камень | P0/P1 по материалу |
| AP Shot | **50.0**, игнорирует броню | пробитие 2 | чугун+железо+доска | P1 по материалу |
| AP Shell (взрывная бронебойная) | **50.0**, игнор.брони | взрыв.сила по сущностям 7 / по блокам 5 | чугун+железо+**гуcкотон** | **факт. P3** (гуcкотон = редстоун) |
| HE Shell (фугас) | **30.0** прямое + взрыв.сила по сущностям **12** / блокам 8 | лучший против толпы/стен | железо+**гуcкотон** | **факт. P3** |
| Мешок картечи (grapeshot) | множественные шарики, дробовой залп | — | шерсть+нить+доска | P1 по материалу |
| Пороховой заряд (сам "патрон" для выстрела) | — | без него пушка не выстрелит вообще | `packed_gunpowder` = гуcкотон×3 = порох+редстоун+вода | **P3 — жёсткий гейт на саму возможность стрелять** |

Вывод по большим пушкам: **лафет, ствол (чугун), Shot и мортирный камень можно собрать в P1**, но реальный первый выстрел случится не раньше **P3**, когда появится редстоун для порохового заряда. До этого пушка — красивый памятник у алтаря.

### 1.4 Create: Radars (`create_radar-0.4.9.4`)

Полный контур автонаведения нашёлся: **Radar Bearing/Receiver/Dish → Network Controller → Auto Yaw/Pitch Controller → Fire Controller → Data Link → Monitor**, плюс `Guided Fuze` (самонаводящийся взрыватель для снаряда) и бинокль для ручного целеуказания.

Ключевой гейт всей сети — **`create:precision_mechanism`** используется в Network Controller, Monitor, Fire Controller, Auto Yaw/Pitch Controller → вся радарная автоматика **гейтится в P2** (Латунь), как и задумано фразой "механизм точности". Радар-тарелка/приёмник — медь+молниеотвод+"industrial_iron_block", тоже не выше P2.

Что даёт сеть: Network Controller с фильтрами целей (только враждебные / только игроки / исключить союзников) → автонаведение и **автоогонь** пушек Big Cannons на всё, что видит радар. С P2 весь набег можно отбивать без единого клика игрока, если хватит боеприпасов.

### 1.5 Create Guardian Beam Defense (скачан отдельно, НЕ в паке — только для оценки)

modrinth slug `create-guardian-beam-defense`, версия `1.3.3b-1.21.1-neoforge`, аддон к Create (зависимость не объявлена явно, но по описанию требует Create).

| Турель | Рецепт | Требует убить | Фаза |
|---|---|---|---|
| **Basic Guardian Beam Turret** | механическая сборка: prismarine bricks + вал + prismarine crystals×2 + стекло×4 + `guardian_beam_capacitor` + цинк-самородки | обычного **Guardian** | **P2–P3** (нужен цинк + рейд на храм океана) |
| **Advanced Guardian Beam Turret** | dark prismarine + `elder_guardian_beam_capacitor` + аналогичная обвязка | **Elder Guardian** (жёстче, дебафф Mining Fatigue в ауре) | **P3** |
| **Beam Reactor Helmet** (ручной лазер-шлем игрока) | незеритовый шлем + `elder_guardian_beam_capacitor` + sturdy sheet + prismarine | Elder Guardian + незерит | **P3–P4** |

Механика: турель заряжается лучом от **кинетики (SU/RPM)** — в тексте тултипа буквально "заряжается со скоростью, зависящей от Rotation Speed", числового фиксированного RPM в данных нет (это, как и автопушка, определяется входной скоростью вала — чем быстрее крутите, тем быстрее перезарядка луча). Базовая турель держит 1 цель в радиусе 17 блоков, продвинутая — 10 целей одновременно. Урон луча в JSON не хранится (Java) — судя по описанию мода (аналог урона гвардиана, стабильный DPS луча, а не залповый) — ставьте как "средний постоянный DPS", проверить Jade/тестом.

## Задача 2 — Бестиарий

### 2.1 Мобы, которые реально есть в паке

**Ваниль** (не переопределена): Zombie, Husk, Drowned, Skeleton, Stray, Spider, Cave Spider (лезет по стенам, яд), Creeper, Enderman, Witch, Phantom (летает), Piglin/Piglin Brute (Нижний мир), Wither Skeleton, Blaze (летает, дальний), Vindicator/Ravager (если рейды пиллагеров включены), Warden (если задет sculk в Deep Dark — **однохитовый урон ~в районе смертельного**, для орды непригоден, только как угроза-беги).

**Хоррор-моды пака — все НЕ ордовые.** Важнейший вывод: все специализированные хоррор-мобы пака спроектированы как **одиночные сталкеры** для атмосферы, а не для боя толпой:

|---|---|---|---|---|
| `cave_dweller` | Cave Dweller | огромный монстр пещер, медленный, очень живучий, ловит по звуку/свету | ❌ один экземпляр, не толпа | 5/5 |
| `imposter` | Imposter / Cutout | подменяет обычного моба-приманку, неожиданная атака | ❌ единичный джампскейр | 4/5 |

## Задача 3 — Баланс набегов (прогноз орды)

Принцип (как в паках на Create — "закон гринда"): игрок должен получить **не таймер ожидания, а рычаг подготовки**. Прогноз орды перед жертвой должен явно показывать — сколько патронов/снарядов начеку, а не просто "будет сложно". Формат ниже — то, что стоит вывести игрокам в GUI/книге квестов ПЕРЕД тем, как они поднесут жертву к алтарю.

**Общие допущения** (нужно перепроверить в игре через Jade — точные числа взяты из данных, где они есть, иначе — стандартные ванильные/оценка):
- HP: Zombie/Husk/Drowned/Skeleton/Stray/Piglin ≈ 20, Spider/Cave Spider ≈ 16/8, Creeper ≈ 20, Wither Skeleton ≈ 20, Blaze ≈ 20, Piglin Brute ≈ 50, Ravager ≈ 100.
- Набег стартует через 60 сек после жертвы — окно на подготовку и первые выстрелы, пока волна ещё идёт к алтарю.
- "Механику ломки стен ордой" в паке сейчас реализовать нечем (см. Enhanced Hordes выше) — до его установки считайте стены надёжной защитой, кроме крипер-подрыва.

### Формат прогноза (для UI/книги)

```
НАБЕГ НА АЛТАРЬ через 60с
Волна 1: 8× Zombie, 3× Skeleton         (суммарно 220 HP)
Волна 2 (+20с): 4× Spider, 1× Creeper   (суммарно 84 HP)
ИТОГО: 304 HP орды
Рекомендуемый боезапас (автопушка AP, 14 dmg/выстрел): 304/14 ≈ 22 → готовьте 35 патронов (запас на промахи/добивание)
```

## Итоговые проверочные шаги (сделать в игре, не на бумаге)

1. Навести Jade на живого Cave Dweller / Imposter / The Obsessed / Northstar-моба и записать реальные HP/урон — тут это байткод, точных чисел из jar не вытащить без декомпиляции.
